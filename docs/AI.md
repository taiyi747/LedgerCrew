# AI 开发任务清单

**LedgerCrew · 账清社｜40 小时｜角色 C**

技术栈：Python 3.14、MiMo API、Microsoft Agent Framework、Pydantic 2。
代码归属：`server/app/agents/`、`fixtures/`。

先阅读 [公共协作约定](PLAN.md)，再按本文件的 AI 编号领取任务。H0 为团队开工时间；每完成一项，在 PR 中附运行方法与验收结果。

## 开工顺序

1. H2 前验证 MiMo 图片输入、工具调用、结构化输出、人工审批和检查点恢复。
2. 与后端确认共享类型、对账工具、依赖注入、事件和工作流恢复方式。
3. 准备合成样例与预期结果，让前后端能在同一组数据上并行验证。

## 任务与验收

负责人：**AI 开发成员**。使用真实 MiMo API；提示词、角色、工具、工作流节点和输出模型纳入版本管理。业务结果必须能够追溯。

- [x] **AI-01｜H0–H2｜框架接入验证。** 在 Python 3.14 验证指定框架包、MiMo 图片输入、工具调用和结构化输出；验证人工等待、文件检查点及重启恢复。密钥只放本地配置。**验收：** 保存可复现的最小验证脚本和脱敏结果；将实际可用参数、模型名称及依赖告知 B。
- [x] **AI-02｜H2–H8｜五个角色。** 定义总管、票据、核对、客服、交付 Agent。每个角色使用独立指令、输入输出和工具集合。**验收：** 总管能安排任务，票据 Agent 能输出带来源的结构化结果。
- [x] **AI-03｜H2–H8｜演示材料与预期答案。** 在 `fixtures/` 准备 6 张合成票据图片、6 条标准流水及预期结果，另备字段不清晰图片。样例明确标注为合成数据。**验收：** B 可独立验证对账，A 可用于完整演示。
- [x] **AI-04｜H4–H16｜工作流与交接。** 使用 `WorkflowBuilder` 定义材料检查、识别、核对、异常分支、人工等待和报告节点。通过 B 提供的工具核对金额。**验收：** 交接包含实际输入、输出和证据；异常会停止在人工待办。
- [x] **AI-05｜H8–H24｜异常核实与恢复。** 生成客户询问草稿，接收老板决定与客户补充，经框架恢复处理。草稿先由老板审核，补充要求通过站内订单页传达。**验收：** 270 元差额能触发核实；客户文字解释不会被自动当作金额一致的证明。
- [x] **AI-06｜H16–H24｜报告 Agent。** 基于 B 的计算结果、证据和人工决定生成摘要与说明。用 Pydantic 校验输出，将金额、引用和业务规则校验放在服务端。**验收：** 缺失信息有标记，报告不补造数据，原始材料可定位。
- [x] **AI-07｜H24–H40｜可靠性与回归。** 设置模型超时、临时故障最多 2 次自动重试、结构错误最多 2 次纠正，以及请求和工具调用上限。测试失败、拒绝、不合法结果、重启恢复；记录实际模型、耗时及可获得的 token 用量。**验收：** 达到上限明确失败或转人工，不以固定结果冒充模型执行；提交前完成真实 MiMo 回归。

## 需要与队友对齐

- 向后端提供工作流工厂、节点定义、人工等待请求和恢复所需信息。
- 复用后端共享模型和金额工具；Agent 负责提取、判断、询问和解释，金额由代码计算。
- 向前端提供角色说明与真实事件示例；运行状态和成果统一经过后端输出。
- 起始依赖为 `agent-framework-core==1.24.0`、`agent-framework-openai==1.18.0`，验证后由后端锁定完整依赖。

## 交给队友的成果

- MiMo 客户端、五个角色、显式工作流、提示词、输出模型及最小验证脚本。
- 6 张合成票据、6 条流水、字段不清晰样例及预期答案。
- 暂停、人工回复、重启和恢复的可复现说明，以及有限重试和调用上限。
- 真实模型调用的脱敏证据、耗时与可获得的 token 用量，以及已知局限。
