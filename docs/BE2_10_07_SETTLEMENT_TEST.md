# BE2-10-07 结算批次与跨期到账测试

## 验收结论

**v0.2 结算与到账核对：BLOCKED，未执行平台结算服务测试。** 仓库没有 `SettlementBatch`、`PlatformRecord`、结算分配/到账关联模型、结算计算 Service、到账匹配 Service、结算 API 或相应 Alembic migration。运行时 OpenAPI 中不存在 `platform` 或 `settlement` 路径；`contracts/API.md` 中对应接口与模型仍是候选设计。没有可调用的 v0.2 服务来验证 15 个业务场景，不能把算术演示或 MVP 对账回归写成平台功能通过。

`docs/P2_DECISIONS.md` 中 `DEC-005`（平台、导出格式和字段口径）、`DEC-009`（资金来源、结算/跨期/内部转账口径）及 `DEC-004`（申报所属期）仍为 `pending`。本次未制定平台符号规则、匹配阈值、批次唯一键或跨期归属规则，未改动业务代码、数据库、API 或决策状态。

## 当前实现边界

| 检查项 | 实际代码状态 | 对本任务的影响 |
| --- | --- | --- |
| `PlatformRecord`、`SettlementBatch`、分配与到账关联 | 无 ORM 模型、迁移或数据访问层 | 无法保存一对多、多对一的来源及分配金额 |
| 平台/支付流水 | 无平台导入或支付流水模型；现有 `BankTransaction` 只属于 MVP `Order` 和 `StatementImport` | 无法确定平台交易、结算批次与银行入账的关系 |
| 结算计算与匹配 Service | 无 | 无法测试确定性、重复扣款、匹配唯一性、事务和重试 |
| 结算 API | 无；运行时 OpenAPI 只有 MVP `/api/v1/orders/{order_id}/reconciliation[/run]` | 无法执行平台批次或到账 API 测试 |
| MVP `ReconciliationBatch/Match` | 发票与银行流水的一对一匹配，匹配差额固定为零 | 不能表示平台订单与多次结算、一个批次与多笔到账 |
| MVP 汇总 | `reconciliation_engine` 按订单期间汇总导入流水；现有测试明确验证重复流水仍计入现金汇总 | 不能当作去重后的平台营业收入或结算净额；内部转账也不能在此自动判定 |

## 题目金额示例的核算

在 Python 3.11 中仅用整数分核算题目给出的数字：

```text
100000 - 10000 - 3000 - 2000 + 500 = 85500 分（855 元）
85500 - 85500 = 0 分
85500 - 84500 = 1000 分（10 元）
```

此结果只证明给定数字的算术关系。各扣减/增加项尚未绑定已确认的平台导出字段，也没有结算 Service 产生 `matched` 或“待核实”结果。因此 **855 元到账一致、845 元产生 10 元待核实差额这两个服务断言尚未执行**。不据此推定其他平台采用同一结算公式。

## 已执行的回归

- 环境：Python 3.11.18；pytest 使用项目隔离的临时 SQLite 数据库和合成数据，未连接真实客户数据库。
- 命令：`server/.venv/py311-env/Scripts/python.exe -B -m pytest -q tests/test_stage4.py tests/test_stage6.py tests/test_mvp_csv_dedup_provenance.py`。
- 结果：**23 passed**。覆盖的是现有 MVP 发票/银行流水对账、期间过滤、异常、权限、文件来源和 CSV 重试边界；**v0.2 平台结算测试数为 0**。
- 运行时 OpenAPI 核对：`platform_settlement_paths=[]`，MVP 对账路径 2 条。
- Python 整数分演算：预期 85500 分；实际 85500 分时算术差额 0 分，实际 84500 分时算术差额 1000 分。该演算不是服务测试。

## 缺陷与后续门禁

本轮未发现可安全修复的 v0.2 结算代码缺陷，因为模块尚不存在。**若复用 MVP 现金汇总作为平台收入或净结算，将有重复计数和跨期误归属风险**；现有 MVP 测试显示重复导入流水仍计入现金汇总，这并非 P2 去重或结算策略。本轮没有改写 MVP 语义。

要继续 BE2-10-07，需先由负责人确认：

1. `DEC-005`：首个平台及导出版本、订单/退款/费用/补贴/调整项和批次 ID 的字段含义、符号与稳定性。
2. `DEC-009`：银行或支付流水来源及授权、批次与到账分配依据、跨期/延迟到账处理、内部转账识别、重复关联与差额待核实规则。
3. `DEC-004`：业务所属期与到账日期如何分别记录及适用。

在这些决策确认并完成 BE2-02/03 的模型、迁移、Service 和 API 后，使用明确标注的合成平台 fixture 为上述 15 个场景补写服务/API 测试；同时验证金额守恒、来源关联、权限、事务回滚、重复请求及审计。未确认前不添加猜测性的结算实现或仅验证 `sum()` 的形式测试。
