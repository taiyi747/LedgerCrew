# 第二阶段：后端开发计划

**LedgerCrew · 账清社｜MVP 验收后启动｜角色：后端开发**

本计划中的首发范围、任务唯一性、审批与资料包行为均为待确认项；以 [第二阶段决策登记表](../P2_DECISIONS.md) 的 `confirmed` 记录为实现门槛。Python 固定 3.11。

前置计划：[MVP 后端任务](../BACKEND.md) · [MVP 公共约定](../PLAN.md)。

## 阶段目标与启动条件

在 MVP 的订单、票据、对账、审批和报告上，增加平台结算、账务分类、版本化政策规则、确定性税务计算和申报材料生成，支撑一位经营者运营完整的财税 Agent 团队。

本文件是第二阶段计划。MVP 主线、权限、幂等和检查点恢复验收后启动；按里程碑推进，不计入原 MVP 的 40 小时排期。代码继续归属 `server/`，Agent 定义和工作流由 AI 成员维护。

首个范围限定一个地区、一类经营主体、一种申报事项和一个平台数据格式。启动时由三人确认，后端将选定范围、所需字段、表单版本、材料及不支持项写入支持范围记录，AI 成员附上官方依据。范围未锁定前可并行准备适配器与契约，具体税务规则和表单映射在锁定后实现。

## 任务清单

- [ ] **BE2-01｜商户与申报领域模型。** 新增商户税务档案、所属期、申报事项、支持范围、必要材料与独立申报任务。经营主体类型和纳税人身份分开保存；“OPC”是产品经营定位，不作为税务身份枚举。**验收：** 资料缺失和不支持的组合可识别；原 MVP 订单继续可运行。
- [ ] **BE2-02｜平台数据与来源追溯。** 接入首个平台实际导出的订单、退款、费用、补贴、结算批次与银行／支付流水。保留原文件、原始行、外部编号、账户、日期和导入批次，生成规范化记录。**验收：** 重复导入不重复记账；有唯一源标识时优先去重，无标识时有受控重复检测。
- [ ] **BE2-03｜结算与到账核对。** 按实际平台账单口径计算应到账，关联订单、退款、费用与调整项，再匹配实际到账。支持有来源依据的一对多／多对一、待到账、跨期到账和自有账户转账，避免跨来源重复计算。**验收：** 样例中 1000−100−30−20＋5＝855 元，到账一致可核对，845 元产生 10 元待核实；项目只在实际结算中扣除一次。
- [ ] **BE2-04｜账务分类与修订。** 保存 AI 分类和科目建议、原始凭证、确认人、修订及汇总口径，提供给后续计算使用。区分销售、退款、平台费用、资金到账和内部转账。**验收：** 人工修订有记录，汇总可复现；银行净到账不直接替代营业收入或应税销售额。
- [ ] **BE2-05｜政策与规则版本。** 保存官方来源、发布机关、发布时间、生效／失效信息、适用地区、主体／身份、所属期、表单版本、抓取时间、快照和审核状态。将审核后的可执行规则与来源关联。**验收：** 按业务所属期选择适用版本；未审核、冲突或缺失规则阻塞相关计算，历史结果仍可复算。
- [ ] **BE2-06｜确定性税务计算。** 将已确认数据、分类及规则输入代码计算，保存公式、参数、舍入口径、中间值、输入快照和规则版本；比率使用 Decimal，最终金额按规则转为整数分。**验收：** 同输入同版本产生同结果；未知身份、材料或政策不会被当作零值或由模型临时决定税率。
- [ ] **BE2-07｜申报表字段与草稿。** 为选定官方表单版本建立字段映射、必填项、校验关系及证据引用，生成版本化草稿与材料缺失清单。区分税务申报、财务报表、工商年报的不同成果。**验收：** 字段能追溯到来源与计算；关键资料不足时草稿标记阻塞，不能批准为完整交付。
- [ ] **BE2-08｜扩展工作流与版本审批。** 对接新增会计、政策、税务、审计节点和检查点，保存阶段成果与人工决定。申报任务状态独立于旧订单，区分资料收集、待核实、计算阻塞、草稿待审和可交付。输入、规则或表单变化使旧审批失效。**验收：** 退回、补充、重启和重试可恢复；旧批准不能发布新草稿，模型不能绕过审批。
- [ ] **BE2-09｜资料包与交付。** 打包申报草稿、账目／结算明细、异常说明、材料清单、规则版本、计算依据和审批记录；发布绑定具体版本并提供有权限的下载。**验收：** 客户只取得已批准版本；内部批准、交付与税务机关受理分别表达，自动登录或提交税务系统另行规划。
- [ ] **BE2-10｜迁移、测试与上线回归。** 编写可回退的数据迁移及规则／模板导入流程，测试平台去重、批次与跨期、内部转账、政策适用、阈值与舍入、表间关系、审批失效和恢复，并回归 MVP。**验收：** 金额与申报字段能按来源复算；旧接口和订单可用，新能力按范围逐步启用。

## 新增接口与共享类型

由后端在 P2-0 更新 [接口设计](../../contracts/API.md)、[提议版 OpenAPI](../../contracts/openapi.json) 和 [Mock 样例](../../contracts/examples/README.md)，向前端与 AI 提供待确认契约；在原有订单、材料和权限体系上增加资源，不重写 MVP 的下单与报告流程。首发范围、具体字段与权限未 confirmed 前，不冻结业务接口或启动其实现。P2-0 当前验收状态见 [P2-0 状态记录](P2-0.md)。

| 能力 | 契约内容 |
| --- | --- |
| 商户税务档案与支持范围 | 地区、主体、身份、所属期、事项、材料要求及可支持状态 |
| 平台导入与结算 | 来源、批次、规范化记录、去重结果、应到账与实际到账关联 |
| 账务建议与确认 | 分类建议、凭证、人工确认、修订和数据版本 |
| 规则查询与审核 | 官方依据、适用条件、版本、审核结果及冲突 |
| 申报任务与计算 | 输入快照、计算版本、阻塞项、字段草稿、证据和人工决定 |
| 申报资料包 | 草稿版本、发布版本、材料清单、计算依据、下载权限和交付记录 |

与 AI 共用的主要类型：`MerchantTaxProfile`、`SettlementBatch`、`AccountingSuggestion`、`PolicyRule`、`TaxCalculation`、`TaxReturnDraft`、`FilingPackage`。新增字段与状态在 P2-0 明确；保留 MVP 共享模型及 API 的兼容性。

## 里程碑与交付

| 里程碑 | 后端交付 | 协作 |
| --- | --- | --- |
| P2-0：范围与契约 | 首个场景、字段、材料、接口样例与模型 | AI 确认官方来源；前端确认页面与状态 |
| P2-1：数据与账务 | 导入、结算、到账、分类和来源追溯 | AI 提供解析与分类建议；前端完成确认体验 |
| P2-2：申报草稿 | 已审核规则、计算、表单映射与版本审批 | AI 完成规则提取和审计；前端展示依据与草稿 |
| P2-3：交付与回归 | 资料包、恢复、迁移、回归和运维说明 | 三人完成完整场景及 MVP 回归 |

交付物：新增 OpenAPI 与样例、迁移、可复算计算代码、规则／表单版本记录、资料包、测试结果与启用／回退说明。全国平台与全部税种逐步扩展，具体税率、申报周期和收费在已验证范围内配置，不使用未经核实的统一假设。
