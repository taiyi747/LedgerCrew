# AIWHO WEBHOOK 中台 · 前后端接口文档

> 版本：v1.1 ｜ 前端页面：`index.html`（作战室任务流转大屏）
> 本文档是前端与后端的对接契约，后端按此实现即可直接接入。

## 业务流程（重要）

客户在前端「客户需求」框下发任务后，任务依次流经四大模块，每个模块内的小猫工位会在电脑上播放对应动画：

```
客户接待  →  票据处理  →  数据核对  →  风险与交付
需求受理      票据录入      账务比对      风险评估
合同登记      票面审核      差异复核      交付归档
```

---

## 1. 通用约定

### 1.1 Base URL

| 环境 | 地址 |
|---|---|
| 本地联调 | `http://localhost:3000`（`node api/mock-server.js` 启动） |
| 测试环境 | `https://test-api.example.com` |
| 生产环境 | `https://api.example.com` |

前端通过 `window.AIWHO_API_BASE` 配置后端地址（在 `index.html` 中 `js/api.js` 之前设置）。未配置或后端不可达时，前端自动回退到内置 Mock 并本地模拟任务流转，页面不会白屏。

### 1.2 统一响应结构

```json
{
  "code": 0,
  "message": "ok",
  "data": { },
  "ts": "2026-11-06T22:00:00+08:00"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| code | int | `0` 成功；非 0 为业务错误码 |
| message | string | 错误描述，成功时为 `"ok"` |
| data | object | 业务数据，见各接口 |
| ts | string | 服务器时间，ISO 8601 |

### 1.3 业务错误码

| code | 含义 | HTTP 状态码 |
|---|---|---|
| 0 | 成功 | 200 |
| 400 | 参数错误 | 400 |
| 401 | 未认证 / Token 无效 | 401 |
| 404 | 接口 / 资源不存在 | 404 |
| 500 | 服务器内部错误 | 500 |

### 1.4 认证与 CORS

```
Authorization: Bearer <access_token>        （生产环境建议必带）
Access-Control-Allow-Origin: *
Access-Control-Allow-Headers: Authorization, Content-Type
```

### 1.5 实时性

- 大屏数据**优先走 WebSocket 推送**（见第 4 节），REST 用于首屏加载与断线兜底轮询。
- 建议：首屏调 REST 拉全量 → 建立 WebSocket 接增量 → 断开时每 30s 轮询 `overview` / `groups` / `tasks/{id}`。

## 2. 枚举定义

### 2.1 模块 `id`（流程顺序固定）

| id | 模块名 | 主题色 | 屏幕动画 |
|---|---|---|---|
| `grp_reception` | 客户接待 | 蓝 | 对话流 |
| `grp_ticketing` | 票据处理 | 琥珀 | 票据扫描 / OCR |
| `grp_reconcile` | 数据核对 | 青 | 账务比对打勾 |
| `grp_delivery` | 风险与交付 | 绿 | 风险护盾 + 交付进度环 |

### 2.2 消息级别 `level`

`blue`（蓝）/ `amber`（琥珀）/ `teal`（青）/ `green`（绿）/ `red`（红）

### 2.3 告警级别 `level`

`urgent`（红）/ `warn`（橙）；前端只展示 `resolved: false` 的告警，无告警时显示"无风险"。

## 3. REST 接口清单

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/overview` | 顶部统计（总任务 / 处理中 / 已交付 / 平均时效） |
| GET | `/api/v1/messages` | 实时消息流（顶部滚动条） |
| GET | `/api/v1/alerts` | 风险告警列表 |
| GET | `/api/v1/groups` | **核心**：四大模块 + 工位（驱动流水线布局） |
| POST | `/api/v1/tasks` | **下发客户任务**（触发流程流转） |
| GET | `/api/v1/tasks/{id}` | 查询任务进度（当前模块 / 是否交付） |

---

### 3.1 获取顶部统计

`GET /api/v1/overview`

| 字段 | 类型 | 说明 |
|---|---|---|
| totalTasks | int | 总任务数 |
| processing | int | 处理中数量 |
| delivered | int | 已交付数量 |
| avgCycleMinutes | int \| null | 平均时效（分钟）；`null` 前端显示 `—` |

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "totalTasks": 12,
    "processing": 2,
    "delivered": 17,
    "avgCycleMinutes": null
  },
  "ts": "2026-11-06T22:00:00+08:00"
}
```

---

### 3.2 获取实时消息流

`GET /api/v1/messages?limit=20`

**查询参数**：`limit`（默认 20，最大 100）、`cursor`（翻页游标，可选）

**响应 `data`**：`{ list: Message[], total: int, nextCursor: string|null }`

**Message 对象**

| 字段 | 类型 | 示例 | 说明 |
|---|---|---|---|
| id | string | `"msg_001"` | 消息 ID |
| text | string | `"任务 #T018 需求受理完成"` | 消息正文 |
| level | string | `"blue"` | 消息级别，见 2.2 |
| source | string | `"reception"` | 来源模块：`reception/ticketing/reconcile/delivery` |
| occurredAt | string | `"2026-11-06T21:30:00+08:00"` | 发生时间，前端计算"x分钟前" |

---

### 3.3 获取风险告警

`GET /api/v1/alerts`

**响应 `data`**：`{ list: Alert[], total: int }`

**Alert 对象**

| 字段 | 类型 | 示例 | 说明 |
|---|---|---|---|
| id | string | `"alert_001"` | 告警 ID |
| title | string | `"差异复核超时 1 单"` | 告警标题 |
| level | string | `"warn"` | `urgent` / `warn` |
| createdAt | string | ISO 8601 | 触发时间 |
| resolved | bool | `false` | 是否已解除 |

---

### 3.4 获取模块与工位（核心接口）

`GET /api/v1/groups`

大屏四条流水线卡片由此接口驱动，**返回顺序即流程顺序**。

**响应 `data`**：`{ list: Group[], total: int }`

**Group 对象（一个模块）**

| 字段 | 类型 | 示例 | 说明 |
|---|---|---|---|
| id | string | `"grp_reception"` | 模块 ID，见 2.1 |
| name | string | `"客户接待"` | 模块名称 |
| accent | string | `"blue"` | 主题色：`blue/amber/teal/green` |
| columns | int | `1` | 保留字段（布局提示） |
| stations | Station[] | | 模块内的小猫工位 |

**Station 对象（一个工位 = 一只小猫 + 一台电脑）**

| 字段 | 类型 | 示例 | 说明 |
|---|---|---|---|
| id | string | `"st_intake"` | 工位 ID（全局唯一） |
| name | string | `"需求受理"` | 工位名称 |

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "id": "grp_reception",
        "name": "客户接待",
        "accent": "blue",
        "columns": 1,
        "stations": [
          { "id": "st_intake",   "name": "需求受理" },
          { "id": "st_contract", "name": "合同登记" }
        ]
      },
      {
        "id": "grp_ticketing",
        "name": "票据处理",
        "accent": "amber",
        "columns": 1,
        "stations": [
          { "id": "st_entry",  "name": "票据录入" },
          { "id": "st_review", "name": "票面审核" }
        ]
      }
    ],
    "total": 4
  },
  "ts": "2026-11-06T22:00:00+08:00"
}
```

> 其余两个模块（`grp_reconcile`、`grp_delivery`）见 `api/mock-server.js` 的 `DATA.groups`。

### 3.5 下发客户任务

`POST /api/v1/tasks`

**请求体**

```json
{ "requirement": "为客户「星辰科技」核对 3 月票据并出具交付报告" }
```

**响应 `data`（Task 对象）**

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 任务 ID，如 `"T0101"`，前端全程以 `#T0101` 展示 |
| requirement | string | 需求描述 |
| createdAt | string | 创建时间 |
| stage | string | 当前所在模块 ID（新任务为 `grp_reception`） |
| done | bool | 是否已完成交付 |

**行为约定**：任务创建后，后端按 `grp_reception → grp_ticketing → grp_reconcile → grp_delivery` 自动推进；每次模块切换时通过 WebSocket 推送 `task.stage_changed`。

---

### 3.6 查询任务进度

`GET /api/v1/tasks/{id}`

响应 `data` 与 Task 对象相同。断线重连、刷新页面后前端可用它恢复任务动画状态。

## 4. WebSocket 实时推送

连接地址：`wss://<host>/ws?token=<access_token>`

统一信封：`{ "event": "...", "data": { }, "ts": "..." }`

| event | data 结构 | 触发时机 | 前端行为 |
|---|---|---|---|
| `overview.update` | 同 `GET /overview` 的 data | 统计变化 | 刷新顶部数字 |
| `message.new` | 单个 Message 对象 | 新消息 | 插到消息条最前 |
| `alert.new` | 单个 Alert 对象 | 新风险 | 刷新「风险」区域 |
| `alert.resolved` | `{ "id": "alert_001" }` | 风险解除 | 刷新「风险」区域 |
| `task.stage_changed` | `{ "taskId", "from", "to", "done" }` | **任务流转到下一模块** | 上游模块置「已完成」，下游模块置「处理中」并播放屏幕动画 |
| `group.update` | 单个 Group 对象 | 模块/工位结构变化 | 重渲染该模块卡片 |

**`task.stage_changed` 示例**

```json
{
  "event": "task.stage_changed",
  "data": {
    "taskId": "T0101",
    "from": "grp_reception",
    "to": "grp_ticketing",
    "done": false
  },
  "ts": "2026-11-06T22:01:30+08:00"
}
```

## 5. 前端对接说明

1. **配置后端地址**——`index.html` 中取消注释并填写：

   ```html
   <script>window.AIWHO_API_BASE = "http://localhost:3000";</script>
   ```

2. **请求层**：`js/api.js` 暴露 `API.getOverview / getMessages / getAlerts / getGroups / submitTask`，后端未就绪时自动回退 Mock 并在前端本地模拟流转（每模块约 3.4 秒），方便并行开发与现场演示。

3. **联调自测**：

   ```bash
   node api/mock-server.js     # 启动 Mock 后端（零依赖）
   ```

   打开页面点「下发任务」，控制台不出现 `[api] ... 回退到内置 Mock` 即接口已打通。

4. **动画状态由前端渲染**：模块卡片有 `idle / active / done` 三态（对应「待处理 / 处理中 / 已完成」），后端只需推送任务走到哪个模块（`task.stage_changed` 或 `tasks/{id}.stage`），小猫打字、屏幕动画、连接线流动、交付提示均由前端自动播放。
